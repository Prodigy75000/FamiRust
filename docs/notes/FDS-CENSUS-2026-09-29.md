# FDS BIOS census

Generated by `scripts/fds-census.py`, which runs `fdstrace` over every
disk in the corpus and folds the rows together. Do not hand-edit.

Corpus: `G:\My Drive\FamiRust\Dumps\Cylum's Famicom Disk System ROM Collection (02-16-2021).zip`
Run: 1800 frames per title (~30s), mash=True autoswap=True

**This is a census of what an unattended run reached.** A routine absent
from it is a routine we did not observe, not a routine nothing calls: a
game that wants a button we never press, or a disk side this dump does not
carry, contributes only what it used before it stopped.

## BIOS bytes the GAME reads directly

Counted while the CPU was executing OUTSIDE `$E000-$FFFF`, with
`$FFFA-$FFFF` dropped because every game reads the vectors.

This is the constraint on what a synthetic image may contain. A byte only
the BIOS reads goes away with the routine that read it; a byte the game
reads has to still be there.

## Titles that drive `$4024`/`$4025` themselves

These keep the hardware transfer engine load-bearing no matter how good the
HLE gets, so the HLE stays strictly additive.

Volume is what separates the two cases, so the table is cut at 16. A game
that writes these registers once or twice at init is poking the drive; a
game that writes them hundreds of times is running its own read loop and
needs the real hardware underneath it whatever the BIOS does.
