# Ricoh 2A03 CPU (NMOS 6502, decimal disabled) — Clean-room Implementation Notes

Sources synthesized:
- nesdev.org/6502_cpu.txt (cycle-by-cycle bus reference — the authority for per-cycle behavior)
- nesdev.org/wiki/CPU_ALL (pinout, P register, 2A03 differences, reset/M2)
- nesdev.org/wiki/6502_instructions + CPU_unofficial_opcodes (opcode matrix, illegals)

The 2A03 is a stock NMOS 6502 core with **decimal mode (BCD) permanently disabled**. Everything else in
the CPU core is identical to a standard 6502. These notes cover ONLY the CPU core; APU/DMA/OAM-DMA stall
cycles are out of scope here.

Conventions in this document:
- **R** = read cycle (CPU drives address, reads data bus). **W** = write cycle.
- Every cycle is exactly one memory access (the 6502 has no idle bus cycles — even "internal operation"
  cycles perform a read, usually a dummy/throwaway read of some address). This is critical for cycle
  accuracy and for the dummy-read tests.
- `PC` = program counter, `S`/`SP` = stack pointer (stack lives at `$0100 + S`), `EAL`/`EAH` = effective
  address low/high byte.
- "increment PC" happens on the same cycle that fetches at PC unless noted.

---

## 1. Register Set

| Reg | Width | Purpose | Power-on / Reset value |
|-----|-------|---------|------------------------|
| A   | 8     | Accumulator | unspecified (tests set explicitly) |
| X   | 8     | Index X | unspecified |
| Y   | 8     | Index Y | unspecified |
| S (SP) | 8  | Stack pointer, stack at `$0100+S`, grows downward | `$FD` after reset (see §7) |
| PC  | 16    | Program counter | loaded from reset vector `$FFFC/$FFFD` |
| P   | 8     | Processor status (flags) | I set on reset; others per reset behavior |

Stack: push writes to `$0100 + S` then `S -= 1`. Pull does `S += 1` then reads `$0100 + S`.
S wraps 8-bit (`$00 - 1 = $FF`); pushes/pulls never leave page `$01`.

### P (status) flag bit layout

```
bit:  7 6 5 4 3 2 1 0
      N V - B D I Z C
```

| Bit | Name | Meaning |
|-----|------|---------|
| 0 | C | Carry |
| 1 | Z | Zero (result == 0) |
| 2 | I | IRQ disable (1 = IRQ masked) |
| 3 | D | Decimal mode — **exists but has NO effect on 2A03** (ADC/SBC always binary) |
| 4 | B | "Break" — not a physical register bit; only appears in the byte pushed to stack |
| 5 | (unused) | Not a physical register bit; reads as 1 when pushed |
| 6 | V | Overflow |
| 7 | N | Negative (bit 7 of result) |

### Behavior of B (bit 4) and unused (bit 5) on push/pull

- **Physically there is no bit 4 or bit 5 register.** They only materialize in the byte written to the
  stack, and are ignored when read back.
- **Pushed value depends on cause:**
  - `PHP` and `BRK` push P with **bit 5 = 1 and bit 4 = 1**.
  - Hardware `IRQ` and `NMI` push P with **bit 5 = 1 and bit 4 = 0**.
  - So: pushed byte = `(P & 0xCF) | 0x20 | (software ? 0x10 : 0x00)` where "software" means PHP/BRK.
    Bit 5 is always 1 in the pushed byte.
- **Pulled value (`PLP`, `RTI`):** bits 4 and 5 of the popped byte are **discarded** — they do not change
  any CPU state. Implementation: internal P has no storage for bits 4/5; force bit5=1, bit4=0 internally,
  or simply mask them out and re-synthesize on push.
- Recommended internal representation: store the 6 real flags (N,V,D,I,Z,C). Synthesize the pushed byte;
  ignore 4/5 on pull.

## 2. 2A03-specific differences from a stock 6502

1. **Decimal mode disabled.** ADC and SBC ALWAYS perform binary arithmetic regardless of the D flag. The
   D flag can still be set/cleared/read by SED/CLD/PHP/PLP and shows up in the pushed P byte, but it never
   changes ADC/SBC results, N, V, Z, or C. **Do not implement BCD adjustment.**
2. **Writes suppressed during RESET** (see §7). The reset "pushes" decrement S three times but perform no
   actual writes.
3. Everything else (illegal opcodes, JMP indirect bug, RMW double write, dummy reads, interrupt polling
   quirks) is identical to a standard NMOS 6502. All the famous NMOS bugs are present.

M2 / clock (informational, not core logic): CPU clock ≈ 1.789773 MHz (NTSC master 21.477272 MHz ÷ 12).
"M2" is the buffered φ2 the bus uses; a CPU cycle is one M2 period. Not needed for instruction correctness,
only for tying the CPU into the wider system clock.

## 3. Cycle-by-cycle addressing modes

Golden rules that make the dummy-read / dummy-write tests pass:

- **Every cycle does a real bus access.** "Internal" cycles read *something* (dummy reads).
- **Indexed reads that cross a page boundary do a dummy read at the wrong (un-fixed) address first**, then
  a corrected read. If no page cross, no extra cycle for READ instructions.
- **Indexed WRITES and all RMW instructions ALWAYS do the dummy read at the un-fixed address** (no page
  cross → still a dummy read, no cycle saved). They never skip the extra cycle.
- **RMW instructions write the ORIGINAL (unmodified) value back on the first write cycle, then the modified
  value on the second write cycle** ("double write"). This is observable and tested.
- PC increments only when fetching from PC.

Legend below: `PC` fetch means "read at PC, then PC++". Address column is the bus address that cycle.

### 3.1 Implied / Accumulator — 2 cycles
```
1  R  PC        fetch opcode, PC++
2  R  PC        dummy read next byte (PC NOT incremented); execute (e.g. INX, ASL A, TAX, CLC)
```

### 3.2 Immediate — 2 cycles
```
1  R  PC        fetch opcode, PC++
2  R  PC        fetch operand, PC++ ; execute
```

### 3.3 Zero page — read
```
1  R  PC        fetch opcode, PC++
2  R  PC        fetch ZP address (EAL), PC++   (EAH = 0)
3  R  00,EAL    read operand
```
Base 3 cycles. Write variant replaces cycle 3 with `W 00,EAL` (store), still 3 cycles.

### 3.4 Zero page — RMW (ASL/LSR/ROL/ROR/INC/DEC + illegals SLO/RLA/SRE/RRA/DCP/ISC) — 5 cycles
```
1  R  PC        fetch opcode, PC++
2  R  PC        fetch ZP address, PC++
3  R  00,EAL    read value
4  W  00,EAL    write the ORIGINAL value back (dummy write); compute modified value
5  W  00,EAL    write modified value
```

### 3.5 Zero page indexed (ZP,X or ZP,Y) — read — 4 cycles
```
1  R  PC        fetch opcode, PC++
2  R  PC        fetch ZP base address, PC++
3  R  00,base   dummy read at un-indexed address; EAL = (base + index) & 0xFF
4  R  00,EAL    read operand
```
The index add wraps within the zero page (high byte stays 0; e.g. `$FF + X=2 = $01`, NOT `$0101`).
Write variant: cycle 4 becomes `W 00,EAL`. Note the ZP,Y form only exists for LDX/STX and illegal
LAX/SAX; all others use ZP,X.

### 3.6 Zero page indexed — RMW — 6 cycles
```
1  R  PC        fetch opcode, PC++
2  R  PC        fetch ZP base, PC++
3  R  00,base   dummy read; EAL = (base+index)&0xFF
4  R  00,EAL    read value
5  W  00,EAL    write original back (dummy); compute
6  W  00,EAL    write modified
```

### 3.7 Absolute — read — 4 cycles
```
1  R  PC        fetch opcode, PC++
2  R  PC        fetch EAL, PC++
3  R  PC        fetch EAH, PC++
4  R  EAH,EAL   read operand
```
Write variant: cycle 4 = `W`. (STA/STX/STY/SAX abs = 4 cycles, no dummy.)

### 3.8 Absolute — RMW — 6 cycles
```
1  R  PC        fetch opcode, PC++
2  R  PC        fetch EAL, PC++
3  R  PC        fetch EAH, PC++
4  R  addr      read value
5  W  addr      write original back (dummy); compute
6  W  addr      write modified
```

### 3.9 Absolute indexed (abs,X / abs,Y) — read — 4 (+1 on page cross) cycles
```
1  R  PC        fetch opcode, PC++
2  R  PC        fetch base low, PC++
3  R  PC        fetch base high, PC++ ; low = (base_low + index); carry = (low > 0xFF)
4  R  (base_high, low&0xFF)   read.
       - If NO page cross (carry==0): this IS the correct address → done, 4 cycles.
       - If page cross (carry==1): this address has the WRONG high byte → it's a dummy read.
5  R  (base_high+1, low&0xFF)   corrected read (only when page crossed) → 5 cycles.
```
Page-cross penalty = +1 cycle for READ instructions ONLY.

### 3.10 Absolute indexed — WRITE — always 5 cycles (NO page-cross saving)
```
1  R  PC        fetch opcode, PC++
2  R  PC        fetch base low, PC++
3  R  PC        fetch base high, PC++
4  R  (base_high, (base_low+index)&0xFF)   ALWAYS a dummy read at the un-fixed high byte
5  W  correct_addr                         write
```
STA abs,X / STA abs,Y / SHA/SHX/SHY/TAS = 5 cycles always.

### 3.11 Absolute indexed — RMW — always 7 cycles
```
1  R  PC
2  R  PC        base low
3  R  PC        base high
4  R  unfixed   dummy read (un-fixed high byte)
5  R  fixed     read value from correct address
6  W  fixed     write original back (dummy); compute
7  W  fixed     write modified
```
(DEC/INC/ASL/LSR/ROL/ROR abs,X and illegals SLO/RLA/SRE/RRA/DCP/ISC abs,X or abs,Y = 7 cycles.)

### 3.12 Indexed indirect (zp,X) — read — 6 cycles
```
1  R  PC        fetch opcode, PC++
2  R  PC        fetch pointer base, PC++
3  R  00,base   dummy read; ptr = (base + X) & 0xFF
4  R  00,ptr        fetch EAL
5  R  00,(ptr+1)&0xFF   fetch EAH   (pointer read wraps in zero page)
6  R  EAH,EAL   read operand
```
Write variant: cycle 6 = `W` (STA/SAX (zp,X) = 6 cycles). RMW variant adds the read+2 writes = 8 cycles
(illegals SLO/RLA/SRE/RRA/DCP/ISC (zp,X)):
```
6  R  EA    read
7  W  EA    write original (dummy)
8  W  EA    write modified
```

### 3.13 Indirect indexed (zp),Y — read — 5 (+1 on page cross) cycles
```
1  R  PC        fetch opcode, PC++
2  R  PC        fetch pointer address, PC++
3  R  00,ptr        fetch EAL
4  R  00,(ptr+1)&0xFF   fetch EAH ; low = (EAL + Y); carry = (low > 0xFF)  (pointer read wraps in ZP)
5  R  (EAH, low&0xFF)   read.
       - no page cross → correct → 5 cycles
       - page cross → dummy read at wrong high byte
6  R  (EAH+1, low&0xFF) corrected read (only on page cross) → 6 cycles
```

### 3.14 Indirect indexed (zp),Y — WRITE — always 6 cycles
```
1  R  PC
2  R  PC        pointer
3  R  00,ptr        EAL
4  R  00,(ptr+1)&0xFF   EAH ; add Y
5  R  unfixed   ALWAYS dummy read at un-fixed high byte
6  W  fixed     write
```
STA (zp),Y and illegal SHA (zp),Y = 6 cycles always.

### 3.15 Indirect indexed (zp),Y — RMW — always 8 cycles
```
1  R  PC
2  R  PC        pointer
3  R  00,ptr        EAL
4  R  00,(ptr+1)&0xFF   EAH ; add Y
5  R  unfixed   dummy read (un-fixed)
6  R  fixed     read value
7  W  fixed     write original (dummy)
8  W  fixed     write modified
```
(Illegals SLO/RLA/SRE/RRA/DCP/ISC (zp),Y = 8 cycles.)

### 3.16 Relative branch (BPL/BMI/BVC/BVS/BCC/BCS/BNE/BEQ) — 2 (+1 taken) (+1 page cross)
```
1  R  PC        fetch opcode, PC++
2  R  PC        fetch signed offset, PC++
   -- evaluate condition. If NOT taken → done, 2 cycles.
3  R  PC        (branch taken) dummy read of the opcode at current PC;
                add offset to PCL: newPCL = PCL + offset (8-bit), keep old PCH for now.
   -- if newPCL did not carry (no page cross) → PC = old_PCH:newPCL → 3 cycles.
4  R  (old_PCH, newPCL)   (page cross) dummy read at un-fixed address; fix PCH (+/-1) → 4 cycles.
```
Offset is signed 8-bit; page cross means the branch target's high byte differs from `(PC after operand)`
high byte. Max 4 cycles.

**Branch interrupt-poll quirk (important for cpu_interrupts test):** For most instructions the interrupt
is polled during the final cycle. Branches poll interrupts at the end of cycle 2 (before the taken
add) — a taken branch does NOT re-poll, so an interrupt that becomes pending during a taken branch's extra
cycle(s) is delayed. Also, a taken branch that does NOT cross a page **fails to poll** on its last cycle in
the specific NMOS timing, meaning the interrupt can be delayed by one instruction. Practical rule that
passes tests: poll for interrupts on the cycle before the last cycle of the branch. If unsure, verify
against cpu_interrupts ROM (see §9).

## 4. Stack / control-flow instructions (cycle sequences)

### 4.1 PHA / PHP — 3 cycles
```
1  R  PC          fetch opcode, PC++
2  R  PC          dummy read (PC not incremented)
3  W  0100+S      push A (PHA) or P-with-B (PHP: bits 4&5 set); S--
```

### 4.2 PLA / PLP — 4 cycles
```
1  R  PC          fetch opcode, PC++
2  R  PC          dummy read
3  R  0100+S      dummy read (pre-increment); S++
4  R  0100+S      pull value → A (PLA, sets N,Z) or P (PLP, ignores bits 4&5)
```
PLP's I-flag change is delayed one instruction for interrupt purposes (§6).

### 4.3 JSR — 6 cycles
```
1  R  PC          fetch opcode, PC++
2  R  PC          fetch target low (ADL), PC++
3  R  0100+S      internal/dummy stack read (no change)
4  W  0100+S      push PCH; S--
5  W  0100+S      push PCL; S--
6  R  PC          fetch target high (ADH), PC++ ; PC = ADH:ADL
```
Note the return address pushed is the address of the last byte of JSR (PC after ADL fetch = target of
RTS's +1). Cycle 3's dummy read of the stack is characteristic.

### 4.4 RTS — 6 cycles
```
1  R  PC          fetch opcode, PC++
2  R  PC          dummy read
3  R  0100+S      dummy read; S++
4  R  0100+S      pull PCL; S++
5  R  0100+S      pull PCH
6  R  PC          dummy read at PC; PC++ (so PC = returnaddr+1)
```

### 4.5 RTI — 6 cycles
```
1  R  PC          fetch opcode, PC++
2  R  PC          dummy read
3  R  0100+S      dummy read; S++
4  R  0100+S      pull P (ignore bits 4&5); S++
5  R  0100+S      pull PCL; S++
6  R  0100+S      pull PCH
```
RTI restores I **before** polling for interrupts (unlike CLI/SEI/PLP), so a pending IRQ is taken
immediately after RTI if unmasked.

### 4.6 BRK — 7 cycles (see §5, shares path with IRQ/NMI)

### 4.7 JMP absolute ($4C) — 3 cycles
```
1  R  PC          fetch opcode, PC++
2  R  PC          fetch ADL, PC++
3  R  PC          fetch ADH ; PC = ADH:ADL
```

### 4.8 JMP indirect ($6C) — 5 cycles — **with the NMOS page-boundary bug**
```
1  R  PC              fetch opcode, PC++
2  R  PC              fetch pointer low (PL), PC++
3  R  PC              fetch pointer high (PH), PC++
4  R  PH:PL           fetch new PCL
5  R  PH:((PL+1)&0xFF) fetch new PCH   ← BUG: high byte of pointer does NOT increment
```
**JMP indirect bug:** the +1 for the high-byte fetch wraps within the same page. If `PL == $FF`, cycle 5
reads from `PH:$00` (same page) instead of `(PH+1):$00`. Example: `JMP ($10FF)` reads PCL from `$10FF` and
PCH from `$1000`. Implement `hi_addr = (ptr & 0xFF00) | ((ptr + 1) & 0x00FF)`.

## 5. Interrupt / reset sequences (all 7 cycles)

BRK, IRQ, and NMI share one 7-cycle micro-sequence; they differ only in (a) whether cycle 2 increments PC,
(b) the B bit in the pushed P, and (c) which vector is read. RESET reuses the frame but suppresses writes.

### 5.1 BRK — 7 cycles
```
1  R  PC          fetch opcode ($00), PC++
2  R  PC          fetch/ignore the signature byte, PC++   (BRK is 2 bytes: PC advances past the operand)
3  W  0100+S      push PCH; S--
4  W  0100+S      push PCL; S--
5  W  0100+S      push P with B=1, bit5=1; S--
6  R  FFFE        fetch vector low  → PCL ; set I flag (after pushing P)
7  R  FFFF        fetch vector high → PCH
```
The pushed PC points to the byte AFTER the BRK signature (BRK_addr + 2), so RTI returns two bytes past BRK.

### 5.2 IRQ (hardware) — 7 cycles (only serviced if I == 0)
```
1  R  PC          dummy fetch of opcode (opcode NOT executed), PC NOT incremented
2  R  PC          dummy fetch, PC NOT incremented
3  W  0100+S      push PCH; S--
4  W  0100+S      push PCL; S--
5  W  0100+S      push P with B=0, bit5=1; S--
6  R  FFFE        fetch vector low ; set I flag
7  R  FFFF        fetch vector high ; PC = vector
```

### 5.3 NMI — 7 cycles (edge-triggered, cannot be masked by I)
Identical to IRQ but vector is `$FFFA/$FFFB` and B=0 in pushed P. NMI is triggered on the high→low edge of
the /NMI line (a level, held low, only causes one NMI — the line must go high then low again for another).

### 5.4 RESET — 7 cycles
```
1  R  PC          dummy read
2  R  PC          dummy read
3  R  0100+S      dummy read (would be push PCH) — WRITE SUPPRESSED; S--
4  R  0100+S      dummy read (would be push PCL) — WRITE SUPPRESSED; S--
5  R  0100+S      dummy read (would be push P)   — WRITE SUPPRESSED; S--
6  R  FFFC        fetch reset vector low  → PCL ; set I flag
7  R  FFFD        fetch reset vector high → PCH
```
Net effect: S is decremented by 3 (so if S started at $00 it ends at $FD — the common "$FD after reset").
No memory is modified. I is set. Other flags (N,V,D,Z,C) are unspecified/unchanged by reset — the internal
P is not cleared; test setups initialize P explicitly. A, X, Y are unaffected by reset.

## 6. Interrupt polling, masking delay, and hijacking

- **Poll point:** For a normal instruction, the CPU samples the IRQ/NMI lines during the *last* cycle
  (specifically before the fetch of the next opcode). If an interrupt is pending at that point, the next
  "instruction" is replaced by the 7-cycle interrupt sequence (opcode fetch happens but is discarded and
  execution is forced to the interrupt path).
- **NMI has priority over IRQ.** NMI is edge-detected and latched; IRQ is level-detected and only acted on
  while I == 0.
- **Delayed I-flag effect for CLI / SEI / PLP:** these instructions change I *after* the interrupt is
  polled for that instruction. So a `CLI` immediately followed by code with a pending IRQ still executes
  ONE more instruction before the IRQ fires. `SEI` conversely allows one more IRQ through in the pending
  case. **RTI does NOT have this delay** — it updates I before polling, so a pending IRQ fires right after.
- **Interrupt hijacking:** The vector to use is chosen at cycle ~4-5 of the interrupt sequence (after PC is
  pushed, when P is about to be pushed / vector selected). If an NMI asserts during a BRK or IRQ sequence
  before that decision point, the sequence **branches to the NMI vector ($FFFA)** instead of $FFFE — but if
  the in-progress instruction was BRK, the pushed P still has **B=1** (so software can detect a hijacked
  BRK). This is the classic "NMI hijacks BRK/IRQ" behavior tested by cpu_interrupts.
- **Branch poll quirk:** see §3.16.

## 7. Flag effects by instruction group (2A03 — binary only)

### ADC — A = A + M + C (binary, D ignored)
```
sum = A + M + C            (full 9-bit)
C = sum > 0xFF
result = sum & 0xFF
Z = (result == 0)
N = result bit7
V = (~(A ^ M) & (A ^ result) & 0x80) != 0
   i.e. V set when A and M have same sign but result differs in sign (signed overflow)
A = result
```

### SBC — A = A - M - (1-C) (binary, D ignored)
Implement as `ADC` with M inverted: `SBC(M) == ADC(M ^ 0xFF)`.
```
value = M ^ 0xFF
sum = A + value + C
C = sum > 0xFF          (C=1 means no borrow)
result = sum & 0xFF
Z, N as usual
V = ((A ^ result) & (value ^ result) & 0x80) != 0
A = result
```
Note: the illegal `SBC #imm ($EB)` is identical to legal `SBC #imm ($E9)`.

### CMP / CPX / CPY — compare (reg - M), sets flags, discards result, does NOT touch V
```
t = reg - M            (as unsigned 16-bit: reg + (M ^ 0xFF) + 1)
C = (reg >= M)         (set if no borrow)
Z = (reg == M)
N = (t & 0x80) bit of the 8-bit low result
V unaffected. A/X/Y unchanged.
```

### AND / ORA / EOR — logical, into A
```
A = A op M ; N = A.bit7 ; Z = (A==0). C,V unaffected.
```

### ASL / LSR / ROL / ROR (accumulator or memory RMW)
- ASL: C = bit7 in; result = value << 1; bit0 = 0.
- LSR: C = bit0 in; result = value >> 1; bit7 = 0.
- ROL: newbit0 = old C; C = bit7 in; result = (value << 1) | oldC.
- ROR: newbit7 = old C; C = bit0 in; result = (value >> 1) | (oldC << 7).
- All set N = result.bit7, Z = (result==0). V unaffected.
- Memory forms are RMW (double write, §3).

### INC / DEC / INX / DEX / INY / DEY — +1 / -1
```
result = (value ± 1) & 0xFF ; N = bit7 ; Z = (result==0). C,V unaffected.
```
Memory INC/DEC are RMW (double write).

### BIT — test bits of M against A
```
Z = ((A & M) == 0)
N = M.bit7
V = M.bit6
A and M unchanged. (Zero-page and absolute forms only.)
```

### Loads (LDA/LDX/LDY) — N,Z from loaded value. Stores (STA/STX/STY) — no flags.
### Transfers: TAX/TAY/TXA/TYA/TSX set N,Z. **TXS does NOT set flags.**
### Flag ops: CLC/SEC/CLI/SEI/CLD/SED/CLV directly set/clear their bit (D has no arithmetic effect).
### NOP — no flags, no effect (timing per addressing mode).

Columns: opcode, mnemonic, addressing mode, base cycles, `+p` = adds 1 cycle on page cross (READ indexed
modes and taken/page-cross branches only). RMW/write indexed modes never get the page-cross bonus (their
base already includes the always-dummy-read cycle). Illegal opcodes marked `*`. Addressing-mode
abbreviations: imp=implied, acc=accumulator, imm=immediate, zp, zpx, zpy, abs, abx (abs,X), aby (abs,Y),
ind (JMP indirect), izx ((zp,X)), izy ((zp),Y), rel.

### 8.2 Unofficial / illegal opcodes

Operations (do the shift/inc on M, then the ALU op on A, flags per the ALU op):
- **SLO** = ASL M; ORA A,M.  (C from ASL, N/Z from ORA result)
- **RLA** = ROL M; AND A,M.
- **SRE** = LSR M; EOR A,M.
- **RRA** = ROR M; ADC A,M.  (V/C from the ADC)
- **DCP** = DEC M; CMP A,M.  (C/Z/N as CMP; V unaffected)
- **ISC** (a.k.a. ISB/INS) = INC M; SBC A,M.

**SAX (store A & X) — no flags:**

| Op | Mnem | Mode | Cyc |
|----|------|------|-----|
| 87 | SAX | zp | 3 |

SAX writes `A & X` to memory. Affects no flags. (It is a write op, no dummy read beyond mode's normal.)

**LAX (LDA + LDX, i.e. A=X=M) — sets N,Z:**

| Op | Mnem | Mode | Cyc | +p |
|----|------|------|-----|----|
| A7 | LAX | zp | 3 | |

| AF | LAX | abs | 4 | |
| BF | LAX | aby | 4 | +p |

LAX loads M into both A and X, sets N,Z. **LAX #imm ($AB) is unstable** — `A = X = (A | magic) & M`
where `magic` is a chip/temperature-dependent constant (commonly $EE, $FF, or $00). Avoid relying on it.

**Immediate ALU illegals:**

| Op | Mnem | Mode | Cyc | Operation / flags |

The imm NOPs read (and discard) one operand byte. The zp/zpx/abs/abx NOPs perform the corresponding

the page-cross dummy read). `1A/3A/5A/7A/DA/FA` behave like `EA` (implied 2-cycle NOP).

**JAM / KIL / HLT (halt the CPU):** opcodes `02 12 22 32 42 52 62 72 92 B2 D2 F2`. These lock the CPU: it
puts `$FF` on the data bus and stops (no further instructions execute). Implement as a permanent halt
state. Cycle count is effectively infinite/undefined.

**Unstable stores (high-byte AND quirk):**

| Op | Mnem | Mode | Cyc | Operation |
|----|------|------|-----|-----------|
| 9F | SHA/AHX | aby | 5 | store A & X & (H+1) |
| 93 | SHA/AHX | izy | 6 | store A & X & (H+1) |
| 9E | SHX | aby | 5 | store X & (H+1) |
| 9C | SHY | abx | 5 | store Y & (H+1) |
| 9B | TAS/SHS | aby | 5 | S = A & X; then store S & (H+1) |
| BB | LAS | aby | 4 (+p) | A = X = S = M & S; N,Z set |

Here `H` = high byte of the target address (before indexing). "Store `reg & (H+1)`" is the classic
unstable behavior. **Additional instability:** if the indexing crosses a page boundary, the stored high
byte gets ANDed INTO the effective address's high byte as well (the value written and the address can both
be corrupted). Common accurate model: `value = reg & (H+1)`; if page crossed during `(base+index)`, the
high byte of the target address becomes `value`. These are analog/edge-case behaviors — TomHarte vectors
encode a specific model; match that model exactly and mark them as "verify". LAS ($BB) is comparatively
stable: `A=X=S = M & S`.

## 9. What each test suite exercises (checklist)

**TomHarte "nes6502" single-step vectors** (per-opcode, per-cycle bus log with `[addr, value, "read"/"write"]`):
- Requires EXACT per-cycle bus activity: every dummy read, the RMW double-write (original then modified),
  the indexed dummy read at the un-fixed high byte, JMP indirect wrap.
- Requires exact final register/flag state including the illegal ops (they include SLO/RLA/…/SHA/SHX/etc.).
  Match the unstable-opcode model the vectors use (they pick a fixed magic constant model).
- Decimal mode: since it's the *nes* 6502 set, ADC/SBC ignore D — implement binary only.
- P: the vectors track the real 6 flags; ensure bit4/bit5 handling on PHP/PLP/BRK/RTI matches.

**Blargg cpu_instrs:** every official (and it also checks common illegals in some sub-tests) instruction's
functional result + flags. Binary ADC/SBC (no BCD). CMP flag rules. Correct RMW results.

**Blargg cpu_interrupts:** interrupt timing — the delayed CLI/SEI/PLP I-flag effect, RTI immediate effect,
NMI/IRQ hijacking of BRK, the branch poll quirk, exact 7-cycle interrupt sequence with correct pushed P
(B bit).

**Blargg cpu_dummy_reads / cpu_dummy_writes:** the dummy read on indexed page cross, the always-dummy-read
on indexed writes and RMW, the RMW dummy write of the original value, the abx-NOP dummy reads. If any dummy
access is missing or on the wrong cycle, these fail.

## 10. Implementation order (recommended)

1. **Legal opcodes + all addressing modes, fully cycle-accurate.** Build the per-cycle state machine (or a
   micro-op list per opcode) so that every memory access lands on the right cycle: dummy reads, indexed
   page-cross dummy read, RMW double-write, JMP indirect bug, stack sequences. Validate against
   TomHarte legal opcodes and Blargg cpu_instrs + cpu_dummy_reads/writes. Get ADC/SBC binary + V/C exactly
   right here.
2. **Interrupts + reset.** Add the shared 7-cycle BRK/IRQ/NMI sequence, RESET (writes suppressed, S-=3, I
   set), interrupt polling at the last cycle, the CLI/SEI/PLP delay, RTI immediate effect, NMI edge latch +
   priority + hijacking, and the branch poll quirk. Validate against Blargg cpu_interrupts.
3. **Illegal opcodes.** Add SLO/RLA/SRE/RRA/SAX/LAX/DCP/ISC (stable), the immediate ALU illegals
   (ANC/ALR/ARR/XAA/AXS/SBC-alias), the NOP family, JAM/KIL, and finally the unstable stores
   (SHA/SHX/SHY/TAS/LAS) — matching whichever magic-constant / high-byte model the TomHarte vectors use.
   Validate against TomHarte full 256 + any illegal-opcode Blargg tests.
